Spotlight project

Respawn

A local, OpenAI Responses API compatible gateway for self-hosted LLMs. It gives OpenAI SDKs a familiar /v1 API while keeping model serving inside your own stack.

What it is

A compatibility layer for local LLM stacks

Respawn stores response state, reconstructs conversation history from previous_response_id, normalizes streaming events, and forwards generation to an OpenAI-compatible Ollama endpoint.

Gateway, not runtime

Respawn intentionally does not implement GPU inference, tokenizers, batching, KV cache management, quantization, or model loading. Those jobs stay in Ollama and the model runtime below it.

OpenAI-shaped behavior

The gateway exposes familiar object shapes, IDs, errors, Responses flows, Chat Completions compatibility, and SDK-oriented contract coverage.

Local-first operations

Postgres or SQLite persistence, API-key auth, tenant-scoped stored responses, structured logs, metrics, and a full Docker Compose stack.

Highlights

Responses API surface, state, tools, observability

Responses API

POST /v1/responses with create, stream, retrieve, input-items, token counting, and delete support.

Chat compatibility

POST /v1/chat/completions passthrough-style compatibility for OpenAI-shaped clients.

Stored state

Postgres persistence, soft deletes, chain-depth limits, and tenant-scoped response history.

SSE streaming

Streaming events are normalized into Responses-style event payloads for SDK-friendly consumption.

Function tools

Tool calling with a small built-in local registry: echo, get_current_time, and calculator.

Observability

Structured JSON logs, Prometheus-compatible metrics, VictoriaMetrics, and a provisioned Grafana dashboard.

Quick start

Run locally with Ollama and the OpenAI SDK

Gateway
ollama serve
ollama pull gpt-oss:120b

cd apps/gateway
python3 -m venv .venv
. .venv/bin/activate
pip install -e ".[test]"
uvicorn src.main:app --host 0.0.0.0 --port 8080
OpenAI Python SDK
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="local-dev-key",
)

response = client.responses.create(
    model="gpt-oss:120b",
    input="Explain Kubernetes in one sentence.",
)

print(response.output_text)

Internals

How the gateway adds behavior on top of Ollama

Stateful Responses

When a request includes previous_response_id, Respawn loads the stored chain, enforces MAX_CHAIN_DEPTH, rejects missing or cross-tenant parents, rebuilds the full chat history, appends the new input, and stores the new response when requested.

Structured Outputs

JSON Schema output is accepted through response_format or SDK-style text.format. Respawn validates the final text, retries once with a repair instruction, and returns an OpenAI-shaped validation error if repair fails.

Prompt Cache and Reasoning

Prompt-cache accounting reports local prefix-cache hits through Responses usage fields. Reasoning requests map reasoning.effort to Ollama think and track reasoning tokens when the backend returns thinking metadata.

Limits

Clear boundaries by design

  • Respawn is a local compatibility gateway, not the hosted OpenAI service.
  • It does not reproduce hosted OpenAI tools unless local equivalents are added.
  • It does not implement GPU inference or model serving.
  • Model quality and tool-calling quality depend on the local model.
  • Streaming and SDK parity may need updates as SDKs evolve.
